## Goal
Turn the current branch (`feat/skybao-cloud-background`) into a standalone desktop app: anything-llm launches in **its own Electron window** instead of the system browser. No installer build (per your choice); it runs from source via `yarn desktop`. Backend uses the **system Node** (per your choice) spawned as a child process.

## Approach (why this shape)
anything-llm is already shaped perfectly for desktop: in production mode the Express server (`server/index.js`) serves the built React SPA from `server/public/` and keeps all data in local SQLite (`server/storage/anythingllm.db`). There is even a `/api/ping` health endpoint.

The one hard constraint: the backend loads **platform-specific native modules** (`@lancedb/lancedb`, `onnxruntime-node`, `canvas`, `sharp`, `@mintplex-labs/mdpdf`). Loading those inside Electron's own process would mean rebuilding them against Electron's ABI — fragile and version-locked. So the robust pattern is: **Electron's main process spawns the real anything-llm server as an ordinary child Node process** and just hosts a `BrowserWindow` pointed at `http://localhost:<port>/`. The server then runs exactly as designed, with zero native-module rebuilds.

## What gets added (all new, isolated under `desktop/`)
Nothing in `server/`, `frontend/`, or `collector/` source is modified. New files only:

1. **`desktop/main.js`** — the Electron main process. On launch it:
   - Picks free ports for `SERVER_PORT` and `COLLECTOR_PORT` (tries 3001/8888, increments if busy — avoids the #1 failure mode of "port in use").
   - Loads (or generates + persists) stable secrets (`JWT_SECRET`, `SIG_KEY`, `SIG_SALT`) into `app.getPath('userData')/secrets.json` so sessions survive restarts. These are passed to the server via the child-process env. Anything in an existing `server/.env` still supplements them (dotenv does not override existing `process.env`), so users can drop LLM keys there as usual.
   - Spawns `node collector/index.js` (optional, non-fatal) and `node server/index.js` with `NODE_ENV=production` + the chosen ports, inheriting stdio so logs appear in the terminal.
   - Polls `http://127.0.0.1:<port>/api/ping` until the server is ready (timeout ~60s), then creates a single `BrowserWindow` (1400×900, sensible min size, anything-llm title) loading that URL.
   - Cleans up: on window-all-closed / before-quit, terminates the child processes (SIGTERM → SIGKILL fallback) so no orphaned servers remain.

2. **`desktop/package.json`** — declares `electron` as a devDependency, `main: "main.js"`, and a `start` script (`electron .`).

3. **`desktop/scripts/build.js`** — portable Node script (no `cross-env` dependency) that:
   - Runs `yarn build` inside `frontend/` with `VITE_API_BASE=/api` baked in (same-origin, exactly like the Docker build), so the SPA talks to the embedded server.
   - Recursively copies `frontend/dist/*` → `server/public/` (the step the Dockerfile does via `COPY`; there is no npm script for it today). Creates/overwrites `server/public`.

4. **`desktop/README.md`** — short usage notes (setup, build, run, where data lives, how to add LLM keys via `server/.env`).

5. **`desktop/.gitignore`** — ignores `desktop/node_modules`.

6. **Root `package.json`** — three new orchestration scripts (no other changes):
   - `"desktop:setup"` → `cd desktop && yarn install`
   - `"desktop:build"` → `node desktop/scripts/build.js`
   - `"desktop"` → `cd desktop && yarn start`

## How you'll run it (first time)
```
yarn setup            # only if not already done (installs server/collector/frontend deps + prisma)
yarn desktop:setup    # install electron into desktop/
yarn desktop:build    # build SPA with /api base + copy into server/public
yarn desktop          # opens anything-llm in its own window
```
Day-to-day afterward: just `yarn desktop` (re-run `yarn desktop:build` only when frontend changes). Backend edits need a restart of `yarn desktop`.

## Data & behavior
- Uses your existing `server/storage/anythingllm.db` and `server/storage/` (STORAGE_DIR left at the server default) — your current workspaces/data carry over.
- Prisma client is already generated in this checkout; `desktop:setup` will additionally run `prisma generate` + `prisma migrate deploy` (idempotent) so it's safe on a fresh clone.
- To configure an LLM, create `server/.env` (from `server/.env.example`) — the server loads it in prod mode and it won't be overridden by the desktop-injected env.

## Out of scope (deliberately)
- No electron-builder/installer output (`.dmg`/`.exe`/`.AppImage`) — per your "run from source" choice.
- No bundled Node runtime — uses your system Node (`/opt/homebrew/bin/node`, v26).
- No changes to existing app source.

## Risk / notes
- Node 26 is well ahead of the repo's `.nvmrc` (18). The server already runs for you under 26, so this is fine — but it's the same risk the CLI already has, not something the desktop wrapper introduces.
- First `desktop:build` takes as long as a normal frontend build; subsequent runs are cached by Vite only if files are unchanged.
